# JL-300: 命令木の再帰的最適化の意味保存

## 対象と定義

全命令木を再帰走査し、逐次合成のskip、定数if、常偽whileを除去する最適化器を実装する。逐次・分岐・while本体の意味同値合同性を証明し、構文帰納法で停止実行関係の双方向保存を示す。補助定理はHoare仕様の同値も与える。固定燃料や実行時間の等しさは主張しない。

状態は `State = Nat → Nat`、変数値は自然数である。減算は自然数の切り捨て減算を用いる。
`Exec c s t` は命令cの有限big-step導出、`run n c s` は燃料nの実行結果である。
`Hoare P c Q` は停止した実行についてのみQを保証する部分正当性を表す。

## 証明する命題

```lean
∀ (c : Cmd), ∀ s t, Exec c s t ↔ Exec (optimize c) s t
```

主定理: `JonnyLean.Imperative.optimize_correct`。
命題に記載した量化・仮定をすべて保持する。有限のテスト入力のみの主張ではない。
関数の等式は全変数での値の一致を意味し、観測リストでの一致は `Agrees` と区別する。

## 独立契約と境界

`contracts/JL300.lean` の名前付き `contract` は上記の型を明記し、対象定理をその型に代入する。
`definition_check` は基礎定義の計算規則を別の命題で確認する。
次の境界・具体例も名前付き命題としてLeanで検査する。

```lean
optimize (.seq .skip (.ite (.truth true) (.seq .skip (.assign 0 (.lit 4))) (.while (.truth true) .skip))) = .assign 0 (.lit 4)
```

0、空の観測集合、更新されない変数も定義の対象である。変数の相異条件がある定理では、その条件を外した結論は主張しない。
`none` は一般には燃料不足であり、単独では非停止の証明としない。停止を含む例題では `∃ t, Exec ...` または具体的終了状態の `Exec` を結論に含める。

## 実装・検証

- 実装: `JonnyLean/Imperative/Equivalence.lean`。
- 契約: `contracts/JL300.lean`。
- Lean 4.29.1 の Init/Std のみ。未使用・private・自動生成宣言も監査対象。
- 許可する公理依存は `propext`、`Quot.sound` のみ。`sorry`、`admit`、独自公理、`Classical.choice` を許可しない。
- 機械検証と自然言語仕様の独立レビュー、人間の承認を区別する。

```sh
lake build JonnyLean.Imperative.Equivalence
lake env lean -DwarningAsError=true JonnyLean/Imperative/Equivalence.lean
lake env lean -DwarningAsError=true contracts/JL300.lean
```
