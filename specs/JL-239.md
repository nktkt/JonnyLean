# JL-239: パーサー結果変換の合成則

## 対象と命題

入力の消費結果を変えず値だけを写すmapPについて、二つの変換を順に行うことが関数合成一回と一致する。

値の関数には単射性を仮定しない。失敗と未消費末尾は保存される。

```lean
theorem contract_JL239 (f : β → γ) (g : γ → δ) (p : Parser α β) : mapP g (mapP f p) = mapP (fun b => g (f b)) p :=
  map_comp f g p
```

上の命題は独立契約の型であり、公開定理 `JonnyLean.Parsing.map_comp` をその型へ代入する。契約の型はLeanによる推論任せにせず明記する。

## 定義と実装

実装は `JonnyLean/Parsing/Core.lean`。定義に対する契約は次の計算式を直接検査する。

```lean
theorem contract_JL239_definition (f : β → γ) (p : Parser α β) : mapP f p = bindP p (fun b => pureP (f b)) := rfl
```

## 証明の構成

bind結合則とpureの左単位則を使い、同じ後続関数へ正規化する。

仕様の必要な仮定は上記の型にすべて記載し、成立させるための例外や結果そのものの仮定を追加しない。

## 境界例

```lean
theorem contract_JL239_boundary : mapP (fun n => n*2) (pureP 3 : Parser Bool Nat) [true] = some (6,[true]) := rfl
```

この具体例に加え、主定理は任意の型・値・有限入力に対する量化を保つ。具体例だけによる一般命題の代用はしない。

## 検証と範囲

- 日本語仕様、主定理、定義契約、境界契約を別の担当が照合する。
- Lean 4.29.1同梱のInit/StdとJonnyLean内部の証明のみを使う。
- `sorry`、`admit`、独自公理、`Classical.choice`を許さず、privateと自動生成宣言を含む公理監査を行う。許容する基礎は`propext`と`Quot.sound`だけ。
