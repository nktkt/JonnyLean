# JL-133: コンパイル後コード長の正確な計数

## 対象と境界

定数・変数・演算の各構文節点がちょうど一命令に対応し、コード長が構文サイズと等しい。評価値の大きさとは独立した構文的な費用モデルを与える。

命令は定数push・環境load・二項add・二項mul。スタック先頭が頂上で、演算時の上二要素 `b :: a` から `a op b` を作る。要素不足は `none`、空プログラムは初期スタックを返す。

## 完全な契約命題

```lean
∀ e : Expr, (bytecode e).length = syntaxSize e
```

公開定理は `JonnyLean.VerifiedPrograms.Machine.compile_length`。固定された名前付き契約は `JonnyLean.Contracts.JL133.contract`。

## 独立した意味モデル

以下は `JonnyLean/VerifiedPrograms/MachineSpecifications.lean` にある固定モデルである。実装対象の関数を呼ばずに再帰または一命令の状態遷移を定義する。各 `*_matches` 補題を構造帰納法で検査してから公開定理と接続する。

```lean
def bytecode : Expr → List Instr
  | .lit n => [.push n]
  | .var x => [.load x]
  | .add a b => bytecode a ++ bytecode b ++ [.add]
  | .mul a b => bytecode a ++ bytecode b ++ [.mul]

def syntaxSize : Expr → Nat
  | .lit _ | .var _ => 1
  | .add a b | .mul a b => 1 + syntaxSize a + syntaxSize b
```

## 証明の構成と再利用補題

構文または入力列の構造帰納法を基礎にし、任意の部分木・式・初期状態について帰納仮定を適用する。蓄積引数・後続列・環境は必要に応じて一般化している。独立モデルとの橋渡しは契約の検査に含まれ、主張を実装の型の別名だけで済ませない。

この課題に関連する再利用補題:

- 公開定理の帰納証明が課題の一般命題を直接検査する。

同じ補題を複数の課題として重複計上しない。評価保存、固定点、サイズ制約、静的検査は異なる明示命題として区別する。

## 境界例

- `one_instruction`: `(bytecode (.var 9)).length = 1`。
- `three_instructions`: `(bytecode (.add (.lit 1) (.lit 2))).length = 3`。

有限例は境界条件の固定に使う。一般命題の証明を例の列挙で代替しない。
