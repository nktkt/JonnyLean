# JL-240: 二段階パーサーの中間末尾仕様

## 対象と命題

pairPが組(b,c)とrestを返す条件を、中間末尾middleが存在して両パーサーが順に成功することとして記述する。

中間末尾を隠さず存在量化し、二番目が元入力を再利用してよいとはしていない。

```lean
theorem contract_JL240 (p : Parser α β) (q : Parser α γ) (input rest : List α) (b : β) (c : γ) : pairP p q input = some ((b,c),rest) ↔ ∃ middle, p input = some (b,middle) ∧ q middle = some (c,rest) :=
  pair_iff p q input rest b c
```

上の命題は独立契約の型であり、公開定理 `JonnyLean.Parsing.pair_iff` をその型へ代入する。契約の型はLeanによる推論任せにせず明記する。

## 定義と実装

実装は `JonnyLean/Parsing/Core.lean`。定義に対する契約は次の計算式を直接検査する。

```lean
theorem contract_JL240_definition (p : Parser α β) (q : Parser α γ) : pairP p q = bindP p (fun b => mapP (fun c => (b,c)) q) := rfl
```

## 証明の構成

最初と二番目のOption結果で場合分けし、some内の組の等式を分解する。

仕様の必要な仮定は上記の型にすべて記載し、成立させるための例外や結果そのものの仮定を追加しない。

## 境界例

```lean
theorem contract_JL240_boundary : pairP (pureP true : Parser Bool Bool) (pureP false) [true] = some ((true,false),[true]) := rfl
```

この具体例に加え、主定理は任意の型・値・有限入力に対する量化を保つ。具体例だけによる一般命題の代用はしない。

## 検証と範囲

- 日本語仕様、主定理、定義契約、境界契約を別の担当が照合する。
- Lean 4.29.1同梱のInit/StdとJonnyLean内部の証明のみを使う。
- `sorry`、`admit`、独自公理、`Classical.choice`を許さず、privateと自動生成宣言を含む公理監査を行う。許容する基礎は`propext`と`Quot.sound`だけ。
- 機械検査の成功と意味のAIレビューを区別し、人間の承認は未記録のままとする。
