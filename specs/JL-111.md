# JL-111: スタックへの一括pushとpopの相殺

## 対象と境界

列を左から順にpushした後、同数の要素をpopすると、逆順の入力列と元のスタックが正確に回復する。既存スタックの内容や入力長に制約はない。

リスト先頭をスタック頂上とする。入力列と初期スタックの型は任意。取り出し数は自然数で0を含み、要素不足は `none` とする。

## 完全な契約命題

```lean
∀ (α : Type u) (xs stack : List α), Stack.popMany xs.length (Stack.pushMany xs stack) = some (xs.reverse, stack)
```

公開定理は `JonnyLean.DataStructures.Stack.popMany_pushMany`。固定された名前付き契約は `JonnyLean.Contracts.JL111.contract`。

## 独立した意味モデル

契約は `Option` の成功・失敗、組、リスト連結・反転・長さを直接記述する。隠れた実装側の正しさ述語を前提にせず、実装の具体的出力をこれらの標準構成子で観測する。

## 証明の構成と再利用補題

構文または入力列の構造帰納法を基礎にし、任意の部分木・式・初期状態について帰納仮定を適用する。蓄積引数・後続列・環境は必要に応じて一般化している。独立モデルとの橋渡しは契約の検査に含まれ、主張を実装の型の別名だけで済ませない。

この課題に関連する再利用補題:

- `Stack.pushMany_spec`。
- `Stack.popMany_prefix`。

同じ補題を複数の課題として重複計上しない。評価保存、固定点、サイズ制約、静的検査は異なる明示命題として区別する。

## 境界例

- `empty_batch`: `Stack.popMany 0 (Stack.pushMany ([] : List Nat) [9]) = some ([], [9])`。
- `lifo`: `Stack.popMany 2 (Stack.pushMany [1, 2] [9]) = some ([2, 1], [9])`。

有限例は境界条件の固定に使う。一般命題の証明を例の列挙で代替しない。
