# JL-235: 左優先選択パーサーの結合則

## 対象と命題

choiceは左が成功すればその結果を使い、失敗時にだけ同じ元入力で右を試す。この選択の結合則を示す。

順序を交換できるとは主張しない。失敗に消費位置を付けないので右は元の入力から再試行する。

```lean
theorem contract_JL235 (p q r : Parser α β) : choice (choice p q) r = choice p (choice q r) :=
  choice_assoc p q r
```

上の命題は独立契約の型であり、公開定理 `JonnyLean.Parsing.choice_assoc` をその型へ代入する。契約の型はLeanによる推論任せにせず明記する。

## 定義と実装

実装は `JonnyLean/Parsing/Core.lean`。定義に対する契約は次の計算式を直接検査する。

```lean
theorem contract_JL235_definition (q : Parser α β) : choice failP q = q := rfl
```

## 証明の構成

最初のパーサーの成否で場合分けし、左優先の制御を同じ形へ簡約する。

仕様の必要な仮定は上記の型にすべて記載し、成立させるための例外や結果そのものの仮定を追加しない。

## 境界例

```lean
theorem contract_JL235_boundary : choice (pureP 1 : Parser Bool Nat) (pureP 2) [] = some (1,[]) := rfl
```

この具体例に加え、主定理は任意の型・値・有限入力に対する量化を保つ。具体例だけによる一般命題の代用はしない。

## 検証と範囲

- 日本語仕様、主定理、定義契約、境界契約を別の担当が照合する。
- Lean 4.29.1同梱のInit/StdとJonnyLean内部の証明のみを使う。
- `sorry`、`admit`、独自公理、`Classical.choice`を許さず、privateと自動生成宣言を含む公理監査を行う。許容する基礎は`propext`と`Quot.sound`だけ。
- 機械検査の成功と意味のAIレビューを区別し、人間の承認は未記録のままとする。
- 契約ファイル: `contracts/JL235.lean`。
