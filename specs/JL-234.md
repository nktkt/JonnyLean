# JL-234: 依存パーサー合成の結合則

## 対象と命題

失敗を伝播するbindによる三段階のパーサー合成は括弧付けに依存せず同じ関数になる。

Safe性や消費の仮定は不要。後続パーサーは直前の解析値に依存してよい。

```lean
theorem contract_JL234 (p : Parser α β) (f : β → Parser α γ) (g : γ → Parser α δ) : bindP (bindP p f) g = bindP p (fun b => bindP (f b) g) :=
  bind_assoc p f g
```

上の命題は独立契約の型であり、公開定理 `JonnyLean.Parsing.bind_assoc` をその型へ代入する。契約の型はLeanによる推論任せにせず明記する。

## 定義と実装

実装は `JonnyLean/Parsing/Core.lean`。定義に対する契約は次の計算式を直接検査する。

```lean
theorem contract_JL234_definition (b : β) (f : β → Parser α γ) : bindP (pureP b) f = f b := rfl
```

## 証明の構成

入力ごとのOption結果の場合分け。成功時は中間値と末尾を明示し同じ残余計算を得る。

仕様の必要な仮定は上記の型にすべて記載し、成立させるための例外や結果そのものの仮定を追加しない。

## 境界例

```lean
theorem contract_JL234_boundary : bindP (pureP 3 : Parser Bool Nat) (fun n => pureP (n+2)) [] = some (5,[]) := rfl
```

この具体例に加え、主定理は任意の型・値・有限入力に対する量化を保つ。具体例だけによる一般命題の代用はしない。

## 検証と範囲

- 日本語仕様、主定理、定義契約、境界契約を別の担当が照合する。
- Lean 4.29.1同梱のInit/StdとJonnyLean内部の証明のみを使う。
- `sorry`、`admit`、独自公理、`Classical.choice`を許さず、privateと自動生成宣言を含む公理監査を行う。許容する基礎は`propext`と`Quot.sound`だけ。
- 機械検査の成功と意味のAIレビューを区別し、人間の承認は未記録のままとする。
