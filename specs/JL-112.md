# JL-112: 複数popの成功条件と分解証明書

## 対象と境界

popManyが成功するための必要十分条件は要求数がスタック長以下であること。成功時には取り出した列と残りを連結すると元のスタックになり、取り出した長さが要求数と一致する。

リスト先頭をスタック頂上とする。入力列と初期スタックの型は任意。取り出し数は自然数で0を含み、要素不足は `none` とする。

## 完全な契約命題

```lean
∀ (α : Type u) (n : Nat) (stack : List α), ((∃ taken rest, Stack.popMany n stack = some (taken, rest)) ↔ n ≤ stack.length) ∧ (∀ taken rest, Stack.popMany n stack = some (taken, rest) → stack = taken ++ rest ∧ taken.length = n)
```

公開定理は `JonnyLean.DataStructures.Stack.popMany_success_iff`。固定された名前付き契約は `JonnyLean.Contracts.JL112.contract`。

## 独立した意味モデル

契約は `Option` の成功・失敗、組、リスト連結・反転・長さを直接記述する。隠れた実装側の正しさ述語を前提にせず、実装の具体的出力をこれらの標準構成子で観測する。

## 証明の構成と再利用補題

構文または入力列の構造帰納法を基礎にし、任意の部分木・式・初期状態について帰納仮定を適用する。蓄積引数・後続列・環境は必要に応じて一般化している。独立モデルとの橋渡しは契約の検査に含まれ、主張を実装の型の別名だけで済ませない。

この課題に関連する再利用補題:

- `Stack.popMany_certificate`。

同じ補題を複数の課題として重複計上しない。評価保存、固定点、サイズ制約、静的検査は異なる明示命題として区別する。

## 境界例

- `zero_on_empty`: `Stack.popMany 0 ([] : List Nat) = some ([], [])`。
- `underflow`: `Stack.popMany 2 [7] = none`。

有限例は境界条件の固定に使う。一般命題の証明を例の列挙で代替しない。
