# JL-247: 完全消費を要求する解析の正しさ

## 対象と命題

completeはパーサーが入力をすべて消費した場合だけ値を返す。残余が空であることを独立した等式で検査する。

接頭辞として成功しただけの解析結果は受理しない。失敗や非空末尾を一律noneへ写す。

```lean
theorem contract_JL247 (p : Parser α β) (input : List α) (b : β) : complete p input = some b ↔ p input = some (b,[]) :=
  complete_iff p input b
```

上の命題は独立契約の型であり、公開定理 `JonnyLean.Parsing.complete_iff` をその型へ代入する。契約の型はLeanによる推論任せにせず明記する。

## 定義と実装

実装は `JonnyLean/Parsing/Primitives.lean`。定義に対する契約は次の計算式を直接検査する。

```lean
theorem contract_JL247_definition (p : Parser α β) (input : List α) (h : p input = none) : complete p input = none := by simp [complete,h]
```

## 証明の構成

パーサー結果と末尾の空/非空を分解し、値の等式をOption.someから抽出する。

仕様の必要な仮定は上記の型にすべて記載し、成立させるための例外や結果そのものの仮定を追加しない。

## 境界例

```lean
theorem contract_JL247_boundary : complete (literal [true]) [true,false] = none := rfl
```

この具体例に加え、主定理は任意の型・値・有限入力に対する量化を保つ。具体例だけによる一般命題の代用はしない。

## 検証と範囲

- 日本語仕様、主定理、定義契約、境界契約を別の担当が照合する。
- Lean 4.29.1同梱のInit/StdとJonnyLean内部の証明のみを使う。
- `sorry`、`admit`、独自公理、`Classical.choice`を許さず、privateと自動生成宣言を含む公理監査を行う。許容する基礎は`propext`と`Quot.sound`だけ。
- 機械検査の成功と意味のAIレビューを区別し、人間の承認は未記録のままとする。
- 契約ファイル: `contracts/JL247.lean`。
