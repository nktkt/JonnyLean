# JL-253: 二つの接頭辞符号器の積構成

## 対象と命題

任意の正しい二つのCodecを、符号語の連結と逐次復号により直積のCodecへ合成できる。

Codecは任意の接尾辞を保持するroundtripと成功入力の復元を保持する構造。単なる孤立した符号語の往復だけは仮定していない。

```lean
theorem contract_JL253 (c : Codec α β) (d : Codec α γ) (value : β × γ) (rest : List α) : decodePair c d (encodePair c d value ++ rest) = some (value,rest) :=
  pair_roundtrip c d value rest
```

上の命題は独立契約の型であり、公開定理 `JonnyLean.Encoding.pair_roundtrip` をその型へ代入する。契約の型はLeanによる推論任せにせず明記する。

## 定義と実装

実装は `JonnyLean/Encoding/Combinators.lean`。定義に対する契約は次の計算式を直接検査する。

```lean
theorem contract_JL253_definition (c : Codec α β) (d : Codec α γ) (b : β) (g : γ) : encodePair c d (b,g) = c.encode b ++ d.encode g := rfl
```

## 証明の構成

連結の結合則により第一符号器へ第二符号語＋末尾を渡し、続いて第二のroundtripを適用する。

仕様の必要な仮定は上記の型にすべて記載し、成立させるための例外や結果そのものの仮定を追加しない。

## 境界例

```lean
theorem contract_JL253_boundary : decodePair unaryCodec unaryCodec (unary 2 ++ unary 0 ++ [true]) = some ((2,0),[true]) := rfl
```

この具体例に加え、主定理は任意の型・値・有限入力に対する量化を保つ。具体例だけによる一般命題の代用はしない。

## 検証と範囲

- 日本語仕様、主定理、定義契約、境界契約を別の担当が照合する。
- Lean 4.29.1同梱のInit/StdとJonnyLean内部の証明のみを使う。
- `sorry`、`admit`、独自公理、`Classical.choice`を許さず、privateと自動生成宣言を含む公理監査を行う。許容する基礎は`propext`と`Quot.sound`だけ。
- 機械検査の成功と意味のAIレビューを区別し、人間の承認は未記録のままとする。
- 契約ファイル: `contracts/JL253.lean`。
