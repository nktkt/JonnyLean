# JL-238: 固定語の連結とパーサーの逐次合成

## 対象と命題

uを解析してからvを解析するUnitパーサーが、u++vを一度に解析するパーサーと一致する。

成功・途中失敗の双方を関数等号で扱う。空の前半または後半も含む。

```lean
theorem contract_JL238 [DecidableEq α] (u v : List α) : bindP (literal u) (fun _ => literal v) = literal (u ++ v) :=
  literal_append u v
```

上の命題は独立契約の型であり、公開定理 `JonnyLean.Parsing.literal_append` をその型へ代入する。契約の型はLeanによる推論任せにせず明記する。

## 定義と実装

実装は `JonnyLean/Parsing/Primitives.lean`。定義に対する契約は次の計算式を直接検査する。

```lean
theorem contract_JL238_definition [DecidableEq α] (a : α) : literal [a] [] = none := rfl
```

## 証明の構成

uの帰納法で文字照合の枝を対応させる。失敗枝はbindの失敗伝播で直ちに一致する。

仕様の必要な仮定は上記の型にすべて記載し、成立させるための例外や結果そのものの仮定を追加しない。

## 境界例

```lean
theorem contract_JL238_boundary : bindP (literal [true]) (fun _ => literal [false]) [true,true] = none := by decide
```

この具体例に加え、主定理は任意の型・値・有限入力に対する量化を保つ。具体例だけによる一般命題の代用はしない。

## 検証と範囲

- 日本語仕様、主定理、定義契約、境界契約を別の担当が照合する。
- Lean 4.29.1同梱のInit/StdとJonnyLean内部の証明のみを使う。
- `sorry`、`admit`、独自公理、`Classical.choice`を許さず、privateと自動生成宣言を含む公理監査を行う。許容する基礎は`propext`と`Quot.sound`だけ。
- 機械検査の成功と意味のAIレビューを区別し、人間の承認は未記録のままとする。
- 契約ファイル: `contracts/JL238.lean`。
