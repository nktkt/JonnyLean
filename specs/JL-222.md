# JL-222: 空言語除去を行う選択の意味保存

## 対象と命題

選択の左右に現れる空言語を除去するsmartAltについて、変換後の受理条件が元の二言語の論理和と一致する。

語長や正規表現の形を制限しない。選択は言語の和で、優先順位を持つパーサーのchoiceとは異なる。

```lean
theorem contract_JL222 (r s : Regex α) (w : List α) : denotes (smartAlt r s) w ↔ denotes r w ∨ denotes s w :=
  smartAlt_correct r s w
```

上の命題は独立契約の型であり、公開定理 `JonnyLean.RegularExpressions.smartAlt_correct` をその型へ代入する。契約の型はLeanによる推論任せにせず明記する。

## 定義と実装

実装は `JonnyLean/RegularExpressions/Smart.lean`。定義に対する契約は次の計算式を直接検査する。

```lean
theorem contract_JL222_definition (s : Regex α) : smartAlt .zero s = s := rfl
```

## 証明の構成

全構文コンストラクターの組合せを検査し、Falseとの論理和を除く。

仕様の必要な仮定は上記の型にすべて記載し、成立させるための例外や結果そのものの仮定を追加しない。

## 境界例

```lean
theorem contract_JL222_boundary : smartAlt (.zero : Regex Bool) .eps = .eps := rfl
```

この具体例に加え、主定理は任意の型・値・有限入力に対する量化を保つ。具体例だけによる一般命題の代用はしない。

## 検証と範囲

- 日本語仕様、主定理、定義契約、境界契約を別の担当が照合する。
- Lean 4.29.1同梱のInit/StdとJonnyLean内部の証明のみを使う。
- `sorry`、`admit`、独自公理、`Classical.choice`を許さず、privateと自動生成宣言を含む公理監査を行う。許容する基礎は`propext`と`Quot.sound`だけ。
- 機械検査の成功と意味のAIレビューを区別し、人間の承認は未記録のままとする。
- 契約ファイル: `contracts/JL222.lean`。
