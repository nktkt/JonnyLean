# JL-135: 生成コードの静的検査と深さ差分

## 対象と境界

任意の式から生成されたコードはすべての初期深さで静的検査に合格し、深さを正確に一つ増やす。空スタック開始も含めコンパイラ出力のスタック不足が起きない。

命令は定数push・環境load・二項add・二項mul。スタック先頭が頂上で、演算時の上二要素 `b :: a` から `a op b` を作る。要素不足は `none`、空プログラムは初期スタックを返す。

## 完全な契約命題

```lean
∀ (e : Expr) (depth : Nat), verifiedDepth (bytecode e) depth = some (depth + 1)
```

公開定理は `JonnyLean.VerifiedPrograms.Machine.check_compile`。固定された名前付き契約は `JonnyLean.Contracts.JL135.contract`。

## 独立した意味モデル

以下は `JonnyLean/VerifiedPrograms/MachineSpecifications.lean` にある固定モデルである。実装対象の関数を呼ばずに再帰または一命令の状態遷移を定義する。各 `*_matches` 補題を構造帰納法で検査してから公開定理と接続する。

```lean
def abstractInstruction : Instr → Nat → Option Nat
  | .push _, n | .load _, n => some (n + 1)
  | .add, n + 2 | .mul, n + 2 => some (n + 1)
  | .add, _ | .mul, _ => none

def verifiedDepth : List Instr → Nat → Option Nat
  | [], n => some n
  | i :: code, n => (abstractInstruction i n).bind (verifiedDepth code)

def bytecode : Expr → List Instr
  | .lit n => [.push n]
  | .var x => [.load x]
  | .add a b => bytecode a ++ bytecode b ++ [.add]
  | .mul a b => bytecode a ++ bytecode b ++ [.mul]
```

## 証明の構成と再利用補題

構文または入力列の構造帰納法を基礎にし、任意の部分木・式・初期状態について帰納仮定を適用する。蓄積引数・後続列・環境は必要に応じて一般化している。独立モデルとの橋渡しは契約の検査に含まれ、主張を実装の型の別名だけで済ませない。

この課題に関連する再利用補題:

- 公開定理の帰納証明が課題の一般命題を直接検査する。

同じ補題を複数の課題として重複計上しない。評価保存、固定点、サイズ制約、静的検査は異なる明示命題として区別する。

## 境界例

- `zero_initial_depth`: `verifiedDepth (bytecode (.add (.var 0) (.lit 1))) 0 = some 1`。
- `nonzero_initial_depth`: `verifiedDepth (bytecode (.mul (.lit 2) (.lit 3))) 7 = some 8`。

有限例は境界条件の固定に使う。一般命題の証明を例の列挙で代替しない。
