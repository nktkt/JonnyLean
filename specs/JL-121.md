# JL-121: 自然数式の変数改名と環境の合成

## 対象と境界

自然数定数・変数・加算・乗算からなる式を改名して評価することは、環境を改名写像で前合成して元の式を評価することと同じ。改名は単射である必要がない。

式は自然数定数、自然数で表す変数名、二項加算・乗算からなる。環境は任意の `Nat → Nat`。変数出現列は順序と重複を保ち、束縛構文は持たない。

## 完全な契約命題

```lean
∀ (f env : Nat → Nat) (e : Expr), meaning env (renamed f e) = meaning (env ∘ f) e
```

公開定理は `JonnyLean.VerifiedPrograms.Expr.eval_rename`。固定された名前付き契約は `JonnyLean.Contracts.JL121.contract`。

## 独立した意味モデル

以下は `JonnyLean/VerifiedPrograms/ExpressionSpecifications.lean` にある固定モデルである。実装対象の関数を呼ばずに再帰または一命令の状態遷移を定義する。各 `*_matches` 補題を構造帰納法で検査してから公開定理と接続する。

```lean
def meaning (env : Nat → Nat) : Expr → Nat
  | .lit n => n
  | .var x => env x
  | .add a b => meaning env a + meaning env b
  | .mul a b => meaning env a * meaning env b

def renamed (f : Nat → Nat) : Expr → Expr
  | .lit n => .lit n
  | .var x => .var (f x)
  | .add a b => .add (renamed f a) (renamed f b)
  | .mul a b => .mul (renamed f a) (renamed f b)
```

## 証明の構成と再利用補題

構文または入力列の構造帰納法を基礎にし、任意の部分木・式・初期状態について帰納仮定を適用する。蓄積引数・後続列・環境は必要に応じて一般化している。独立モデルとの橋渡しは契約の検査に含まれ、主張を実装の型の別名だけで済ませない。

この課題に関連する再利用補題:

- `rename_identity`。
- `rename_comp`。

同じ補題を複数の課題として重複計上しない。評価保存、固定点、サイズ制約、静的検査は異なる明示命題として区別する。

## 境界例

- `literal_unchanged`: `renamed Nat.succ (.lit 7) = .lit 7`。
- `merged_variables`: `meaning id (renamed (fun _ => 3) (.add (.var 0) (.var 1))) = 6`。

有限例は境界条件の固定に使う。一般命題の証明を例の列挙で代替しない。
