# JL-236: 一文字検査パーサーの正確な成功条件

## 対象と命題

Boolean述語を満たす先頭一文字だけを消費するsatisfyの成功を、入力のcons分解と述語成立で完全に特徴付ける。

先頭文字以外を検索しない。空入力および先頭が条件を満たさない入力は失敗する。

```lean
theorem contract_JL236 (test : α → Bool) (input rest : List α) (a : α) : satisfy test input = some (a,rest) ↔ input = a::rest ∧ test a = true :=
  satisfy_iff test input rest a
```

上の命題は独立契約の型であり、公開定理 `JonnyLean.Parsing.satisfy_iff` をその型へ代入する。契約の型はLeanによる推論任せにせず明記する。

## 定義と実装

実装は `JonnyLean/Parsing/Primitives.lean`。定義に対する契約は次の計算式を直接検査する。

```lean
theorem contract_JL236_definition (test : α → Bool) : satisfy test [] = none := rfl
```

## 証明の構成

入力のnil/consとBoolean条件の場合分けにより結果値と末尾の等式を取り出す。

仕様の必要な仮定は上記の型にすべて記載し、成立させるための例外や結果そのものの仮定を追加しない。

## 境界例

```lean
theorem contract_JL236_boundary : satisfy id [false,true] = none := rfl
```

この具体例に加え、主定理は任意の型・値・有限入力に対する量化を保つ。具体例だけによる一般命題の代用はしない。

## 検証と範囲

- 日本語仕様、主定理、定義契約、境界契約を別の担当が照合する。
- Lean 4.29.1同梱のInit/StdとJonnyLean内部の証明のみを使う。
- `sorry`、`admit`、独自公理、`Classical.choice`を許さず、privateと自動生成宣言を含む公理監査を行う。許容する基礎は`propext`と`Quot.sound`だけ。
- 機械検査の成功と意味のAIレビューを区別し、人間の承認は未記録のままとする。
- 契約ファイル: `contracts/JL236.lean`。
