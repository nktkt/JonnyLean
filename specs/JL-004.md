# JL-004: 交わらない有限集合の和集合の濃度

## 対象・集合の表現

任意の型 `α : Type u` 上の有限集合を扱う。和集合の計算には要素の等号を判定する `DecidableEq α` を要求する。空集合を含み、要素が自然数であるとの制限は設けない。

```lean
structure JonnyLean.FiniteSet (α : Type u) where
  elems : List α
  nodup : elems.Nodup
```

`elems` は重複のない列挙であり、`nodup` はその証明である。`x ∈ A` の意味は `x ∈ A.elems`、濃度 `card A` は `A.elems.length` とする。重複を許すリストの長さを集合の濃度とみなすことはしない。

列挙の順序は表現上のデータなので、Lean の構造の等号 `A = B` と数学的な集合の等しさを区別する。集合としての等しさは `Equivalent A B := ∀ x, x ∈ A ↔ x ∈ B`、包含は `Subset A B := ∀ x, x ∈ A → x ∈ B` で定義する。定理 `card_eq_of_equivalent` によって、同じ要素を列挙する二つの表現の濃度が等しいことを証明する。この定理には等号判定も不要である。

交わらないことは、共通の要素がないという意味に展開する。

```lean
def JonnyLean.FiniteSet.Disjoint (A B : FiniteSet α) : Prop :=
  ∀ x, x ∈ A → x ∈ B → False
```

これは通常の `A ∩ B = ∅` に相当するが、この課題では別個の交差演算を導入しない。

## 和集合の意味と命題

`union A B` は `A.elems` に、`B.elems` のうち `A` に含まれない要素だけを追加する。したがって和集合自体は、交わらないという仮定なしで定義できる。出力は重複なし証明を持つ `FiniteSet α` である。

```lean
(union A B).elems =
  A.elems ++ B.elems.filter (fun x => decide (x ∉ A.elems))
```

意味の保証として、任意の入力について次を証明する。

```lean
JonnyLean.FiniteSet.mem_union [DecidableEq α]
  (A B : FiniteSet α) (x : α) :
  x ∈ union A B ↔ x ∈ A ∨ x ∈ B
```

主定理は次の型を持つ。

```lean
JonnyLean.FiniteSet.card_union_of_disjoint [DecidableEq α]
  (A B : FiniteSet α) (h : Disjoint A B) :
  card (union A B) = card A + card B
```

量化されるのは任意の二つの有限集合であり、唯一の数学的仮定は共通の要素がないことである。非空性、要素の具体的な値、列挙の順序は仮定しない。

## 証明と独立契約

交わらないなら、`B` の全要素はフィルターを通過する。よって和集合の列挙の長さは二つの長さの和になる。一般の和集合でも重複は除去され、その membership が通常の和集合と一致することを別に証明する。表現によらない濃度の証明は、共通の membership から列挙の順列を構成し、順列が長さを保つことを用いる。

- 実装: `JonnyLean/FiniteSet/Basic.lean`。
- 契約: `contracts/JL004.lean`。
- `JL004Contract.target` は `Disjoint` と `card` を使わず、要素 membership とリスト長の完全な型に主定理を直接代入する。
- `unionMembership` は和集合の membership、`unionNodup` は出力の重複なし性、`representationInvariant` は列挙順序に依存しない濃度を独立に要求する。
- 境界例は空集合どうし、左右どちらかの空集合、交わらない `{0}` と `{1}`、同じ集合 `{0}` どうしである。最後の例では出力が `[0]` となり、濃度を誤って `2` にしないことを検査する。

Lean `4.29.1` の同梱ライブラリのみを使う。Mathlib、`sorry`、`admit`、新たな公理は導入しない。公開定理と名前付き契約の実際の公理依存は `propext` と `Quot.sound` である。これは既存の `List.nodup_append`、`List.filter_eq_self` 等の標準補題を通じる依存であり、プロジェクトの許可方針に明示する。`Classical.choice` と `sorryAx` には依存しない。
