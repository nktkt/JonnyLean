# JL-223: 連結の空言語・空語簡約の意味保存

## 対象と命題

smartSeqは空言語との連結を空言語にし、空語との連結を相手へ簡約する。この処理が全体の連結言語を保存する。

語の具体値やnullable性の仮定は不要。末端以外の構文はそのまま連結する。

```lean
theorem contract_JL223 (r s : Regex α) : denotes (smartSeq r s) = JonnyLean.Languages.concat (denotes r) (denotes s) :=
  smartSeq_correct r s
```

上の命題は独立契約の型であり、公開定理 `JonnyLean.RegularExpressions.smartSeq_correct` をその型へ代入する。契約の型はLeanによる推論任せにせず明記する。

## 定義と実装

実装は `JonnyLean/RegularExpressions/Smart.lean`。定義に対する契約は次の計算式を直接検査する。

```lean
theorem contract_JL223_definition (r : Regex α) : smartSeq .zero r = .zero := rfl
```

## 証明の構成

構文の場合分けと、言語連結の空元・単位元法則を用いる。

仕様の必要な仮定は上記の型にすべて記載し、成立させるための例外や結果そのものの仮定を追加しない。

## 境界例

```lean
theorem contract_JL223_boundary : smartSeq (.eps : Regex Bool) (.atom true) = .atom true := rfl
```

この具体例に加え、主定理は任意の型・値・有限入力に対する量化を保つ。具体例だけによる一般命題の代用はしない。

## 検証と範囲

- 日本語仕様、主定理、定義契約、境界契約を別の担当が照合する。
- Lean 4.29.1同梱のInit/StdとJonnyLean内部の証明のみを使う。
- `sorry`、`admit`、独自公理、`Classical.choice`を許さず、privateと自動生成宣言を含む公理監査を行う。許容する基礎は`propext`と`Quot.sound`だけ。
- 機械検査の成功と意味のAIレビューを区別し、人間の承認は未記録のままとする。
- 契約ファイル: `contracts/JL223.lean`。
