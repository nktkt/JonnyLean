# JL-237: 固定語パーサーの接頭辞仕様

## 対象と命題

literalパーサーがUnitとrestを返すのは、入力が指定語wordにrestを連結したものの場合に限る。

指定語は空でもよい。成功は接頭辞一致であり、残りの文字を捨てない。

```lean
theorem contract_JL237 [DecidableEq α] (word input rest : List α) : literal word input = some ((),rest) ↔ input = word ++ rest :=
  literal_iff word input rest
```

上の命題は独立契約の型であり、公開定理 `JonnyLean.Parsing.literal_iff` をその型へ代入する。契約の型はLeanによる推論任せにせず明記する。

## 定義と実装

実装は `JonnyLean/Parsing/Primitives.lean`。定義に対する契約は次の計算式を直接検査する。

```lean
theorem contract_JL237_definition [DecidableEq α] (input : List α) : literal [] input = some ((),input) := rfl
```

## 証明の構成

固定語の構造帰納法と入力先頭の等号判定。先頭一致を除いて残りに帰納仮定を適用する。

仕様の必要な仮定は上記の型にすべて記載し、成立させるための例外や結果そのものの仮定を追加しない。

## 境界例

```lean
theorem contract_JL237_boundary : literal [true,false] [true,false,true] = some ((),[true]) := by decide
```

この具体例に加え、主定理は任意の型・値・有限入力に対する量化を保つ。具体例だけによる一般命題の代用はしない。

## 検証と範囲

- 日本語仕様、主定理、定義契約、境界契約を別の担当が照合する。
- Lean 4.29.1同梱のInit/StdとJonnyLean内部の証明のみを使う。
- `sorry`、`admit`、独自公理、`Classical.choice`を許さず、privateと自動生成宣言を含む公理監査を行う。許容する基礎は`propext`と`Quot.sound`だけ。
- 機械検査の成功と意味のAIレビューを区別し、人間の承認は未記録のままとする。
- 契約ファイル: `contracts/JL237.lean`。
