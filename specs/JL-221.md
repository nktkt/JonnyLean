# JL-221: 正規表現の空語受理判定

## 対象と命題

空言語・空語・一文字・選択・連結・Kleene閉包からなる正規表現のnullable計算が、空語の言語意味と同値であることを示す。

アルファベットは任意の型であり、等号判定は不要。空集合を閉包しても空語は受理する。

```lean
theorem contract_JL221 (r : Regex α) : nullable r = true ↔ denotes r [] :=
  nullable_correct r
```

上の命題は独立契約の型であり、公開定理 `JonnyLean.RegularExpressions.nullable_correct` をその型へ代入する。契約の型はLeanによる推論任せにせず明記する。

## 定義と実装

実装は `JonnyLean/RegularExpressions/Syntax.lean`。定義に対する契約は次の計算式を直接検査する。

```lean
theorem contract_JL221_definition (r s : Regex α) : nullable (.seq r s) = (nullable r && nullable s) := rfl
```

## 証明の構成

正規表現の構造帰納法。連結が空語を含む条件を両言語の空語所属へ分解する。

仕様の必要な仮定は上記の型にすべて記載し、成立させるための例外や結果そのものの仮定を追加しない。

## 境界例

```lean
theorem contract_JL221_boundary : nullable (.star (.zero : Regex Bool)) = true := rfl
```

この具体例に加え、主定理は任意の型・値・有限入力に対する量化を保つ。具体例だけによる一般命題の代用はしない。

## 検証と範囲

- 日本語仕様、主定理、定義契約、境界契約を別の担当が照合する。
- Lean 4.29.1同梱のInit/StdとJonnyLean内部の証明のみを使う。
- `sorry`、`admit`、独自公理、`Classical.choice`を許さず、privateと自動生成宣言を含む公理監査を行う。許容する基礎は`propext`と`Quot.sound`だけ。
- 機械検査の成功と意味のAIレビューを区別し、人間の承認は未記録のままとする。
- 契約ファイル: `contracts/JL221.lean`。
