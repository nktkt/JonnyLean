# JL-248: 解析値の追加条件によるフィルター

## 対象と命題

guardPの成功は元パーサーの同じ値・同じ末尾での成功と、解析値へのBoolean検査成立の両方を要求する。

検査は解析値に作用し、入力を追加消費しない。不成立時に別の解析を再試行する機能ではない。

```lean
theorem contract_JL248 (test : β → Bool) (p : Parser α β) (input rest : List α) (b : β) : guardP test p input = some (b,rest) ↔ p input = some (b,rest) ∧ test b = true :=
  guard_iff test p input rest b
```

上の命題は独立契約の型であり、公開定理 `JonnyLean.Parsing.guard_iff` をその型へ代入する。契約の型はLeanによる推論任せにせず明記する。

## 定義と実装

実装は `JonnyLean/Parsing/Primitives.lean`。定義に対する契約は次の計算式を直接検査する。

```lean
theorem contract_JL248_definition (test : β → Bool) (p : Parser α β) : guardP test p = bindP p (fun b => if test b then pureP b else failP) := rfl
```

## 証明の構成

元結果とBoolean条件の分岐で両方向を検証し、結果値の等式を条件へ代入する。

仕様の必要な仮定は上記の型にすべて記載し、成立させるための例外や結果そのものの仮定を追加しない。

## 境界例

```lean
theorem contract_JL248_boundary : guardP (fun n => n > 3) (pureP 2 : Parser Bool Nat) [] = none := rfl
```

この具体例に加え、主定理は任意の型・値・有限入力に対する量化を保つ。具体例だけによる一般命題の代用はしない。

## 検証と範囲

- 日本語仕様、主定理、定義契約、境界契約を別の担当が照合する。
- Lean 4.29.1同梱のInit/StdとJonnyLean内部の証明のみを使う。
- `sorry`、`admit`、独自公理、`Classical.choice`を許さず、privateと自動生成宣言を含む公理監査を行う。許容する基礎は`propext`と`Quot.sound`だけ。
- 機械検査の成功と意味のAIレビューを区別し、人間の承認は未記録のままとする。
