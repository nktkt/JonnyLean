# JL-117: 連想リストの更新とシャドーイング

## 対象と境界

最初の一致を採用する自然数キーの連想リストで、putは指定キーだけを更新する。重複キーを許し、上書きと異なるキーの更新交換をlookupの意味で証明する。

キーは自然数で0を含み、値型は任意。連想リストに重複キーを許し、先頭の一致を採用する。欠損キーの検索は `none`。

## 完全な契約命題

```lean
∀ (α : Type u) (query key : Nat) (value : α) (m : List (Nat × α)), lookup query (Assoc.put key value m) = if query = key then some value else lookup query m
```

公開定理は `JonnyLean.DataStructures.Assoc.lookup_put`。固定された名前付き契約は `JonnyLean.Contracts.JL117.contract`。

## 独立した意味モデル

以下は `JonnyLean/DataStructures/SpecificationModels.lean` にある固定モデルである。実装対象の関数を呼ばずに再帰または一命令の状態遷移を定義する。各 `*_matches` 補題を構造帰納法で検査してから公開定理と接続する。

```lean
def lookup (key : Nat) : List (Nat × α) → Option α
  | [] => none
  | (k, v) :: rest => if k = key then some v else lookup key rest
```

## 証明の構成と再利用補題

構文または入力列の構造帰納法を基礎にし、任意の部分木・式・初期状態について帰納仮定を適用する。蓄積引数・後続列・環境は必要に応じて一般化している。独立モデルとの橋渡しは契約の検査に含まれ、主張を実装の型の別名だけで済ませない。

この課題に関連する再利用補題:

- `Assoc.put_shadow`。
- `Assoc.put_commute`。

同じ補題を複数の課題として重複計上しない。評価保存、固定点、サイズ制約、静的検査は異なる明示命題として区別する。

## 境界例

- `new_key`: `lookup 2 (Assoc.put 2 9 []) = some 9`。
- `shadowed_key`: `lookup 2 (Assoc.put 2 9 [(2, 4)]) = some 9`。

有限例は境界条件の固定に使う。一般命題の証明を例の列挙で代替しない。
