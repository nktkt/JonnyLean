# JL-231: 固定語からの正規表現構築

## 対象と命題

語の各文字をatomとし連結するliteral構築器が、ちょうどその語だけを受理する。

文字型に等号判定を要求するのは実行可能な境界例のみ。主定理は任意の型で成立する。空の固定語はeps。

```lean
theorem contract_JL231 (u w : List α) : denotes (literal u) w ↔ w = u :=
  literal_correct u w
```

上の命題は独立契約の型であり、公開定理 `JonnyLean.RegularExpressions.literal_correct` をその型へ代入する。契約の型はLeanによる推論任せにせず明記する。

## 定義と実装

実装は `JonnyLean/RegularExpressions/Transformations.lean`。定義に対する契約は次の計算式を直接検査する。

```lean
theorem contract_JL231_definition (a : α) (w : List α) : literal (a::w) = .seq (.atom a) (literal w) := rfl
```

## 証明の構成

固定語への帰納法。先頭atomの意味により分解前半が一文字と確定し、残りに帰納仮定を適用する。

仕様の必要な仮定は上記の型にすべて記載し、成立させるための例外や結果そのものの仮定を追加しない。

## 境界例

```lean
theorem contract_JL231_boundary : accepts (literal [true,false,true]) [true,false] = false := by decide
```

この具体例に加え、主定理は任意の型・値・有限入力に対する量化を保つ。具体例だけによる一般命題の代用はしない。

## 検証と範囲

- 日本語仕様、主定理、定義契約、境界契約を別の担当が照合する。
- Lean 4.29.1同梱のInit/StdとJonnyLean内部の証明のみを使う。
- `sorry`、`admit`、独自公理、`Classical.choice`を許さず、privateと自動生成宣言を含む公理監査を行う。許容する基礎は`propext`と`Quot.sound`だけ。
- 機械検査の成功と意味のAIレビューを区別し、人間の承認は未記録のままとする。
- 契約ファイル: `contracts/JL231.lean`。
