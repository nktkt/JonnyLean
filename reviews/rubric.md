# JonnyLean 初版の独立レビュー基準

レビュー担当は実装担当と別のコンテキストで、仕様、数学コード、契約、監査結果を読む。
Lean が検査した命題と、日本語の仕様が意図する命題を比較する。機械検査の成功だけを
根拠に承認してはならない。人間の承認を代行した記録を作ってはならない。

記録する項目:

| criterion | 確認内容 |
| --- | --- |
| definition | 自然数、偶数などの定義が仕様に一致するか |
| quantifiers | 全称・存在量化と対象領域が一致するか。0を落としていないか |
| assumptions | 仮定を追加していないか。結論を仮定に含めていないか |
| conclusion | 証明している結論が仕様と一致するか |
| proof | 証人と推論が正しいか。公理や未完成の証明で穴埋めしていないか |
| coverage | 全数学モジュールが監査対象に含まれるか。対象定理が存在するか |
| audit | 契約と公理監査が通り、記録が検査対象の内容に結び付いているか |

重大な未解決指摘があれば `decision` は `request_changes` とする。
承認するときは各項目に具体的な根拠を書き、`fingerprint` コマンドが出す `inputs` を
レビュー記録に保存する。記録には担当の種類 `ai` と名前を明示する。

この記録は署名ではなく、誰が何を確認したかの自己申告と変更検知のための証跡である。
AIによる意味の確認、Leanの機械検証、人間の承認を区別する。
